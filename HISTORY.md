# История разработки IS Manager

## 2026-11-26 — первая интеграция

Начата самостоятельная реализация в новом репозитории. Сопоставлены история Basic Memory, реализация Переговорки, Faceless, LLM Provider, Passgen и генератора моделей угроз. Основной язык Python. Зафиксированы карта переноса, состав контейнеров, лицензии и порядок эксплуатации.

Реализованы четыре раздела в общей оболочке, локальный первичный вход, TOTP, каталоги, диагностика и управление сеансами. Добавлены Git-обновление, откат и согласованные копии тома. В тестовом каталоге выявлена несовместимость проверки IP SAN в ldap3 на Python 3.12. TLS переведён на проверку имени и IP средствами OpenSSL. Реальный OpenLDAP прошёл LDAPS и STARTTLS, вложенные группы, неверный пароль, смену CA и отзыв сеансов. Chromium прошёл навигацию всех разделов при ширине 390 и 1366 пикселей. Добавлены проверки четырёх инструментов и сценарии запуска настоящих моделей.

## 2026-11-26 — исправления после первой установки

В чистом окружении обнаружены конфликт имени Python-модуля operator и права 0600 при git clone. Помощник переименован в host_helper, Docker назначает владельца исходникам при COPY. Проверены имена каталогов и фазовый журнал обновления, добавлены тесты режима обслуживания и восстановления после прерывания. GitHub Actions для начальной интеграции подтвердил 20 тестов, два настоящих TLS-подключения к OpenLDAP и браузерный проход. На CPU выполнена фактическая транскрибация аудио и видео, в том числе после прерванной загрузки модели.

## 2026-11-26 — совместимость с Active Directory

Проверены LDAPS и STARTTLS с Samba AD DC 4.17 в отдельной сети. Вход по UPN, короткому имени и доменному имени связан с одним objectGUID. Проверены вложенная группа и отзыв доступа после смены CA. Добавлены выбор порядка проверки профилей, отдельное разрешение входа пользователей и администраторов, импорт CA из PEM/DER. Публичный обновляемый профиль поддерживает сохранённые настройки предыдущих версий.

## 2026-11-26 — запись архива и переход с ранних сборок

На работающем экземпляре исправлена передача stdout в утилиту tar. Обновление выполняет копирование перед сменой версии. Добавлен контрольный тест записи потока, установщик умеет использовать исправленный инструмент выбранного релиза.

Проверено обновление действующей установки из GitHub. Синтетический черновик модели угроз и результат обезличивания после переходов 0.1.0 → 0.1.1 → 0.1.2 открыты по прежним адресам через HTTPS. Проверка релизов из браузера запустила установленный помощник systemd.

## 2026-11-26 — эксплуатационные проверки 0.1.3

GitHub Actions развернул релиз из исходников, запустил модель и восстановил контрольный файл. В чистом окружении Ubuntu 24.04.5 установщик развернул v0.1.3 за 15 минут 49 секунд. Повторная установка заняла 5 секунд и сохранила данные. На отдельном стенде пройден прямой переход с 0.1.1 на 0.1.3. На сервере через интерфейс пройдены обновление, откат и повторное обновление между 0.1.2 и 0.1.3. Проверены ссылки на существующие пользовательские результаты, возврат к состоянию копии и работа после отказа при восстановлении повреждённого архива. [Результаты испытаний](docs/VERIFICATION.md)

## 2026-11-27 — сетевой доступ и администрирование 0.2.0

Из «Переговорки» перенесены управление доступом пользователей, поиск и выгрузка событий аудита. В системную панель добавлены публичный адрес и статус местного обработчика GigaAM. Количество неудачных входов учитывается по IP клиента, в том числе за доверенным прокси. Успешный вход освобождает зарезервированную попытку.

Установщик и Compose поддерживают прямые HTTP и HTTPS и передачу HTTP от обратного прокси с внешним TLS. Режим переключается на существующих данных. Контейнер проверяет непосредственного отправителя, публичный Host и переданную схему HTTPS. Проверены три сетевых режима в Gunicorn и переход между ними в Chromium с Nginx, в том числе обработка записи, обезличивание, пароли и сохранность анкеты. [Настройка сети](docs/ADMIN.md#сетевой-доступ)

## 2026-11-27 — сопровождение 0.2.1

Поиск по журналу сопоставляет имя со списком ID пользователей перед отбором событий. Для фильтра типа события задана явная текстовая метка. Устранена зависимость тестового задания от доступности стороннего APT-репозитория на GitHub runner.

## 2026-11-27 — установка рядом с другими сервисами

В README и руководстве администратора добавлены отдельные команды для чистой Ubuntu и сервера с работающим Docker. Приведены пример публикации HTTP на свободном порту и команда создания второго экземпляра с отдельным каталогом и именем Compose.

## 2026-11-27 — автоматическая транскрибация папок в 0.3.0

В административный раздел добавлены ресурсы хранения по образцу «Переговорки». Правило связывает входную локальную папку или SMB-ресурс с местом для публикации TXT. Worker использует уже загруженную GigaAM и сохраняет тайм-коды речевых фрагментов. Готовую расшифровку можно восстановить из SQLite. При замене записи сохраняется предыдущая собственная версия TXT. Удаление исходника включается отдельно для каждого правила.

На изолированном стенде проверен весь путь от сохранения правила в браузере до фактической расшифровки через SMB под учётной записью Samba AD. [Проверка выпуска](docs/VERIFICATION.md#030--27-ноября-2026)

## 2026-11-27 — пакетное обезличивание в 0.4.0

Для браузерных пакетов и наблюдения за папками введён отдельный обработчик на образе web с локальными моделями NER и OCR. Администратор может выбрать существующий ресурс SMB с доменной учётной записью. Добавлены разбор нескольких поколений Excel и Word, CSV с разными кодировками и разделителями и смешанных PDF. Ошибки, результат и повторный приём учитываются по каждому документу. Внешние имена выходных файлов нейтральны. [Работа с пакетами и папками](docs/TEXT_TOOLS.md#пакет-из-браузера)

## 2026-11-27 — обратная связь со стенда предприятий и выпуск 0.5.0

В `app/__init__.py` и `app/auth.py` четыре модуля получили изолированное рабочее пространство браузера. Создание материалов сохраняет прежнюю проверку владельца. В `app/directory.py` и форме каталога добавлен поиск пользователей и групп с назначением административных прав. Сохранён синхронный клиент LDAPS/STARTTLS.

Установщик и `scripts/network_config.py` поддерживают отдельный внешний URL и loopback backend за HTTP- или HTTPS-прокси. Обработчик GigaAM публикует этапы и числовые показатели ресурсов. Проекты Passgen и генератора модели угроз использованы для восстановления компоновки рабочих экранов. Для обезличивания разобраны документы, вызвавшие ошибки на предприятии. Материалы испытаний остались вне Git и образов. [Проверки](docs/VERIFICATION.md#050--27-ноября-2026)

## 2026-11-27 — рабочее пространство и обновления в 0.6.0

Обновлён обзор четырёх инструментов. Из последних материалов можно открыть пакет обезличивания и продолжить анкету на достигнутом шаге. Личные списки получили поиск и страницы по 50 материалов. Готовую стенограмму и архив модели угроз можно скачать прямо из списка.

В обезличивании добавлено сохранение проверенного предпросмотра в течение 30 минут. Сервер сверяет владельца, версию приложения и отпечаток результата. На телефоне первый вариант пароля доступен при свёрнутых настройках. Административные функции собраны в шести разделах, поиск и фильтры работают в соответствующих реестрах. Проверен возврат к запрошенному внутреннему экрану после входа.

Панель обслуживания получает ход команды от помощника. Во время подготовки новых образов прежняя версия продолжает обслуживать запросы. Готовая стенограмма и изменения в открытом пакете появляются без повторной загрузки документа. На ноутбуке основной экран каждого инструмента помещается в окно 1366×768.
