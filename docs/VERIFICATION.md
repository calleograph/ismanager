# Проверка выпусков IS Manager

Проверки первого выпуска выполнены 26 ноября 2026 года на синтетических материалах. Для повторения используйте команды из PROJECT.md и руководств модулей.

| Сценарий | Фактический результат |
| --- | --- |
| Ядро приложения | Временная БД, первичный пароль, обязательная смена, TOTP, отказ повтора кода, отзыв сеансов, роли, CSRF и ограничение попыток проверены автоматизированно |
| Браузер | Chromium прошёл разделы и смену темы при ширине 1366 и 390 пикселей. Проверены все четыре способа генерации пароля в браузере и на сервере |
| Каталоги | OpenLDAP и Samba AD DC прошли вход по LDAPS и STARTTLS, допуск по вложенной группе и отрицательные проверки пароля и сертификата |
| Транскрибация | Локальный worker продолжил прерванную загрузку весов. Без доступа к сети распознаны русская синтетическая фраза длительностью 6,94 секунды и видео с 55 секундами звука. Время обработки на проверенном CPU составило 3,24 и 25,53 секунды. Тишина и повреждённая запись дали диагностируемую ошибку |
| Обезличивание | Проверены локальные веса NER, OCR скана, контроль секретов, изоляция истории и загрузка производных документов. Полный профиль на примере длиной 58 000 знаков занял 4,45 секунды |
| Модель угроз | Результат по всем 243 угрозам для двух профилей совпал с исходным калькулятором. Анкета прошла 11 шагов. Все 20 документов из полного комплекта повторно открыты |
| GitHub Actions | Проверяются Python-тесты, реальные OpenLDAP и Samba AD DC, Web Crypto и браузерная навигация. Для релизного тега запускаются установка с нуля, GigaAM и восстановление контрольного файла из копии. Результаты привязаны к конкретному коммиту |

Скорость распознавания и NER зависит от сервера и материала. Тестовый AD использовал Samba. В этом цикле проверен CPU-профиль.

## Развёртывание и сохранность данных

Релиз v0.1.3 собран и запущен заново в GitHub Actions на Ubuntu 24.04. Пройдены 24 теста Python с 10 дополнительными вариантами, два реальных теста OpenLDAP, два теста Samba AD DC, проверка Web Crypto и браузерная навигация. Вторая задача развернула web и worker, распознала аудио и видео и проверила содержимое файла, восстановленного из резервной копии. [Журнал релизной проверки](https://github.com/calleograph/ismanager/actions/runs/45884527429)

Установщик тега v0.1.3 проверен отдельно в чистом окружении Ubuntu 24.04.5 с systemd, собственным Docker-демоном и общим с хостом ядром. На старте отсутствовали Git, Python, Docker и рабочие тома приложения. При лимите 6 CPU и 12 ГиБ памяти установка заняла 15 минут 49 секунд, повторный запуск — 5 секунд. Установщик поставил Docker 29.1.3 и Compose 2.40.3, загрузил модели и дождался готовности обоих сервисов. Помощник systemd был активен. Через HTTPS проверены вход после смены начального пароля, семь вариантов пароля, распознавание OGG с экспортом, замена адреса электронной почты в выгрузке, все 11 шагов анкеты с получением трёх читаемых DOCX и проверка обновлений на GitHub. После повторной установки пароль и результаты сохранились.

На отдельном действующем экземпляре через веб-интерфейс созданы черновик модели угроз и результат обезличивания. Кнопками администрирования выполнены переходы 0.1.2 → 0.1.3 → 0.1.2 → 0.1.3. После каждого перехода документы открылись под владельцем по прежним ссылкам. После восстановления снимка сохранились исходные результаты, а добавленный позже черновик исчез. При попытке восстановления архива без корректной базы установщик удалил временный том и вернул в работу прежнюю установку.

Проверен и прямой переход с 0.1.1 на 0.1.3. На стенде Ubuntu 24.04.5 без предустановленных Git и Docker сначала развернули 0.1.1 и использовали все четыре раздела через HTTPS. После запуска отдельного установщика релиза 0.1.3 и перезапуска всего окружения сохранились пароль администратора, стенограмма с экспортом, результат обезличивания и три документа модели угроз. Оба сервиса вернулись в состояние healthy.

На этом экземпляре 24 чтения главной страницы по HTTPS с четырьмя одновременными запросами дали медиану 20 мс и 95-й процентиль 25 мс. Измерение относится к небольшому набору синтетических данных после прогрева сервиса.

## 0.2.0 · 27 ноября 2026

- В отдельных контейнерах Chromium прошёл прямые HTTPS и HTTP, HTTPS через Nginx и возврат к прямому HTTPS. На обычном HTTP-адресе браузер сообщил `isSecureContext=false`. В обоих сетевых сценариях получены семь паролей, обезличенный текст, стенограмма русской OGG-записи и сохранённый черновик анкеты. После смены режима сохранились пароль, анкета и сертификат прямого HTTPS.
- Для Nginx использован [пример из поставки](nginx.conf.example). Запрос от постороннего TCP-пира отклонён с кодом 403, запрос через доверенный прокси с неверным именем или схемой — с кодом 400. Подписанный сеанс HTTP не прошёл проверку в HTTPS. На стенде отдельно проверена пересылка через loopback хоста с автоматическим определением шлюза Docker.
- Проверены блокировка доменного пользователя, завершение его сеансов, повторный допуск и расчёт лимита при успешных и ошибочных входах из одной сети.
- Журнал проверен на выгрузке 517 подходящих событий с фильтрами и навигацией. Пользователь без административной роли не получил журнал. При устаревшем сообщении от GigaAM панель указала на потерю связи.

## 0.2.1 · 27 ноября 2026

В GitHub Actions прошли 41 тест Python с десятью дополнительными вариантами, два сценария OpenLDAP, два сценария Samba AD DC и браузерные проверки. Установщик последовательно включил HTTP, HTTPS через прокси и прямой HTTPS с сохранением контейнера обработчика. Отдельный стенд с Nginx открыл все четыре раздела в Chromium, а восстановление резервной копии вернуло содержимое контрольного файла. [Журнал релиза](https://github.com/calleograph/ismanager/actions/runs/45937701456)

Действующая установка обновлена с 0.1.3 через 0.2.0 на 0.2.1. При каждом обновлении создана резервная копия. После явного переключения на локальный HTTP адрес интерфейса ответил на запросы с хоста и из отдельного сетевого пространства Docker. Проверены страница входа, атрибуты cookie, перенаправление гостя на вход и ответ проверки готовности. Веб-контейнер и обработчик GigaAM находятся в состоянии healthy.

На общем Docker-сервере параллельно с работающим IS Manager из публичного v0.2.1 развернули второй экземпляр командой `install.sh --shared-host` с отдельными каталогом, именем Compose и портом. Установка с новыми томами и загрузкой модели заняла 5 минут 21 секунду. Оба контейнера второго экземпляра прошли проверки готовности. После переключения тестовой установки с HTTPS на HTTP страницы входа и проверки состояния одновременно открывались на обоих портах. Созданный в тестовой базе черновик отсутствовал в рабочей. Попытка установки на уже опубликованный порт Docker завершилась до создания конфигурации, томов и контейнеров.
