# Транскрибация в IS Manager

Откройте **Обзор → Открыть записи** или раздел **Транскрибация** (`/transcription/`). В форме **Новая запись** выберите аудио или видео и нажмите **Расшифровать запись**. Во время отправки браузер показывает ход передачи. После приёма в карточке видны очередь, проверка дорожки и ход распознавания. Страница обновляет показатели каждые две секунды. Можно закрыть её и позднее вернуться через **Мои записи** или **Обзор → Последние материалы**.

Готовую стенограмму можно скачать кнопкой **TXT** в списке записей. Чтобы поправить текст, откройте запись, внесите изменения в поле **Текст записи** и нажмите **Сохранить правки**. Кнопка **Скачать TXT** выдаёт сохранённую версию. При уходе со страницы с несохранёнными правками браузер предложит остаться. Для поиска давней записи используйте **Поиск по имени записи** и переходы по 50 записей. При ошибке откройте карточку и выберите **Повторить обработку** или **Выбрать другую запись**.

Мини-терминал показывает агрегированные показатели обработчика GigaAM. CPU измеряется в эквиваленте занятых логических ядер за интервал, память — в МиБ. Учитываются доступные контейнеру ядра и ограничения cgroup v2. Память контейнера включает файловый кеш. На системах без этих счётчиков отображаются показатели процесса. В системном разделе администратору также доступны характеристики сервера, свободное место на диске данных и версии компонентов.

Один файл может занимать до 512 МиБ и длиться до шести часов. Поддерживаются распространённые контейнеры, в том числе WAV, MP3, MP4/M4A, MKV/WebM, Ogg/Opus, FLAC, AVI и MOV. Из видео извлекается первая звуковая дорожка.

Полная GigaAM v3 E2E RNNT распознаёт русскую речь и расставляет знаки препинания. Текст нормализует сама модель. Длительные паузы отделяют абзацы. Результат можно отредактировать, скопировать и выгрузить в TXT. После правок доступна исходная версия для сверки имён и терминов. Исходный файл и стенограмма видны владельцу записи в приложении. Кнопка удаления стирает их из рабочего хранилища. Резервные копии имеют отдельный срок хранения.

## Обработка и хранение

Образ из `Dockerfile.worker` содержит FFmpeg, CPU-версию PyTorch, Silero VAD с локальной моделью ONNX и пакет GigaAM. Поставщик, зафиксированная ревизия `7447938d791c4f3e643386ee22c33777004293a5`, модель, монофонический PCM 16 кГц и сегментация Silero по паузам соответствуют реализации «Переговорки». Для загружаемых файлов IS Manager использует собственную постоянную очередь. Один worker загружает веса один раз и обрабатывает записи по порядку. Чтение аудио потоковое. Для файлов VAD передаёт GigaAM фрагменты речи продолжительностью до 12 секунд и сохраняет контекст между блоками.

При первом старте worker скачивает checkpoint (449 МБ) и токенизатор с официального CDN, сверяет SHA-256 и записывает их в том `/models`. Прерванная загрузка продолжается с сохранённого смещения. При следующем старте подготовленные файлы используются без обращения к сети. Синтез речи, внешние API и учётная запись для распознавания не требуются. Статус подготовки виден в разделе транскрибации. Подробности запуска доступны через `docker compose logs worker`.

В закрытой сети положите оба файла с указанными именами в каталог, который worker видит как `/models`. UID 10001 должен иметь доступ к каталогу и файлам.

| Файл | SHA-256 |
| --- | --- |
| [v3_e2e_rnnt.ckpt](https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/v3_e2e_rnnt.ckpt) | `f60c62fe45902d967000770a12f260de7c5ac4d4b8e5e852f1df8c548e3958b5` |
| [v3_e2e_rnnt_tokenizer.model](https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/v3_e2e_rnnt_tokenizer.model) | `828c12c991019eef952a960661f25a92d6ad279591e2ea466b4aeddf1d20a18a` |

Файлы записей находятся в `/data/media`, состояние очереди и стенограммы — в SQLite основного приложения. При остановке worker поставленные задачи сохраняются. После следующего запуска прерванная запись обрабатывается с начала. После двух прерываний обработчик показывает ошибку, а владелец может повторить задачу вручную. Сбой подготовки модели сохраняет очередь и вызывает повторную попытку через минуту. Worker работает в одном экземпляре на том данных.

## Наблюдение за папками

Администратор может настроить автоматическую расшифровку поступающих записей. Например, файл `Совещание.ogg` во входной папке даст `Тексты IS Manager/Совещание.txt`. В TXT используется UTF-8. Каждая распознанная фраза начинается с диапазона времени от начала записи.

```text
[00:00:02.200 – 00:00:05.840] Добрый день. Начинаем совещание.
```

### Подключить ресурс

1. Откройте **Система → Хранилища**. Создайте локальную папку или ресурс SMB. Одно подключение можно выбрать в нескольких правилах, входной и выходной ресурсы могут использовать разные учётные записи.
2. Для адреса `\\files.example.org\records\meetings` укажите сервер `files.example.org`, общий ресурс `records` и подпапку `meetings`. Введите домен, имя пользователя и пароль отдельно. По умолчанию используется порт 445. Приложение подключается к SMB2/3 по NTLM от указанной доменной учётной записи. Пароль шифруется ключом установки. Для смены пароля сохраните ресурс с новым значением. Если домен разрешает только Kerberos, примонтируйте ресурс на хосте и передайте его контейнерам как локальную папку.
3. Сохраните ресурс и нажмите **Проверить**. Проверка подтверждает возможность открыть и перечислить папку. Для обработки нужны права чтения записей, для публикации — создания и переименования файлов в папке результата. Для удаления оригиналов требуется соответствующее право во входной папке.

Локальные пути отсчитываются от `/watch` внутри контейнеров. В обычной поставке это отдельный том экземпляра. Уже примонтированные на сервере каталоги можно передать как подкаталоги `/watch`. Например, такой `compose.override.yaml` подключает существующий каталог обоим контейнерам. Путь на сервере замените своим. Учётной записи контейнера с UID 10001 нужны права на чтение входных записей и запись в выбранную папку вывода.

```yaml
services:
  web:
    volumes:
      - type: bind
        source: /srv/recordings
        target: /watch/meetings
        read_only: true
        bind:
          create_host_path: false
  worker:
    volumes:
      - type: bind
        source: /srv/recordings
        target: /watch/meetings
        bind:
          create_host_path: false
```

После сохранения файла выполните `sudo /opt/ismanager/scripts/manage.py start`, затем выберите тип «Локальная папка» и путь `meetings`. Для сетевого ресурса, заведённого в интерфейсе как SMB, настройка Compose не требуется. Если тот же локальный каталог нужен для обезличивания, добавьте такой же bind в сервис `redactor` с правами чтения входа и записи в папку результатов.

### Настроить правило

В **Система → Правила** добавьте правило, задайте название, входной ресурс и при необходимости подпапку. По умолчанию результаты попадут в подпапку **Тексты IS Manager** прямо под входной. Чтобы записывать в другое место, выберите выходной ресурс и его подпапку. Для вывода рядом с оригиналами явно выберите тот же ресурс и тот же путь. Отметьте **Включить наблюдение** и сохраните правило.

Обход охватывает файлы непосредственно в выбранной папке. Для вложенных каталогов можно завести свои правила. Worker ждёт двух наблюдений стабильного файла. Интервал по умолчанию составляет 15 секунд и задаётся через `WATCH_POLL_SECONDS` в `.env`. Для долгой загрузки с паузами записывайте во временный файл и переименовывайте его в окончательное имя после копирования. Распознавание выполняет локальная GigaAM v3 E2E RNNT на русском языке. Действуют ограничения по 512 МиБ и шести часам на запись. Состояние обхода и ошибки доступны в правиле. Личные ручные загрузки остаются в разделе «Транскрибация».

| Что произошло | Действие IS Manager |
| --- | --- |
| В папке появился новый файл | После стабилизации ставит его в очередь и записывает TXT с тайм-кодами речевых фрагментов |
| Уже есть одноимённый непустой TXT при первом обнаружении | Пропускает запись и сохраняет исходник, включая правила с включённым удалением |
| Изменилось содержимое исходной записи | Пересчитывает результат. Для предыдущего собственного TXT сохраняется прежняя версия. При совпадении имён или внешних правках результат может получить уточнённое имя |
| Собственный TXT удалён или опустел | Восстанавливает последнюю расшифровку из базы, когда ресурс доступен. Повторное распознавание для восстановления не требуется |
| Установленная связь с SMB оборвалась | Показывает ошибку и повторяет операцию после восстановления доступа |

**Удаление исходника выключено при создании правила.** Если его включить, обработчик сначала запишет и перечитает TXT, затем проверит версию и контрольную сумму исходника. Ранее обработанные записи сохраняются. На локальной файловой системе worker запрашивает блокировку Linux read lease перед удалением. Обычно для этого файл должен принадлежать UID 10001. Если права или файловая система не позволяют подтвердить безопасное удаление, TXT и оригинал сохраняются, причина видна в правиле. После обработки служебная копия аудио освобождается. Расшифровка хранится также в базе IS Manager, а доступ к опубликованному TXT регулируют права самой папки. Резервная копия IS Manager содержит правила, зашифрованные реквизиты и сохранённые тексты. Файлы на подключённых ресурсах и в отдельном томе `/watch` включайте в резервное копирование хранилища.

Чтобы сменить место записи TXT, в форме правила раскройте **Папка для результата**. Отдельно можно раскрыть **Хранение исходных записей** и указать, когда удалять успешно расшифрованный источник. В карточке подключения **Порт и подпапка SMB** собраны необязательные параметры сетевого ресурса.

## Ускоритель NVIDIA

Для CPU достаточно стандартной установки. Для переключения уже установленного приложения на CUDA установите NVIDIA Container Toolkit и драйвер, совместимый с CUDA 12.8, и добавьте следующие параметры в `.env`. Если строка уже существует, измените её значение.

```dotenv
ASR_DEVICE=cuda
TORCH_INDEX_URL=https://download.pytorch.org/whl/cu128
```

Добавьте `compose.override.yaml` рядом с Compose-файлом и повторите `./install.sh`.

```yaml
services:
  worker:
    gpus: all
```

## Поставщики и лицензии

- Пакет GigaAM и карточка весов GigaAM v3 указывают MIT. Веса загружаются во время установки и хранятся отдельно от кода IS Manager. [Код и лицензия GigaAM](https://github.com/salute-developers/GigaAM/tree/7447938d791c4f3e643386ee22c33777004293a5), [карточка модели](https://huggingface.co/ai-sage/GigaAM-v3)
- Silero VAD и модель для определения речи распространяются по MIT. [Silero VAD](https://github.com/snakers4/silero-vad)
- PyTorch и TorchAudio распространяются по BSD с уведомлениями о сторонних компонентах. ONNX Runtime использует MIT. Образ сохраняет лицензионные файлы установленных пакетов. [PyTorch](https://github.com/pytorch/pytorch/blob/main/LICENSE), [TorchAudio](https://github.com/pytorch/audio/blob/main/LICENSE), [ONNX Runtime](https://github.com/microsoft/onnxruntime/blob/main/LICENSE)
- IS Manager запускает FFmpeg и ffprobe как системные программы из Debian. Условия зависят от состава сборки FFmpeg, распространяемый Debian пакет включает лицензии зависимостей в `/usr/share/doc`. [FFmpeg Legal](https://ffmpeg.org/legal.html)

## Проверка распознавания

В каталоге проекта выполните следующую команду после подготовки модели. Она запускает отдельный процесс распознавания и требует ещё около 2 ГиБ свободной памяти. Проверка использует временную БД, короткую синтетическую фразу на русском (eSpeak NG), видео длительностью более 45 секунд, тишину и повреждённый файл.

```sh
docker compose run --rm --no-deps -e PYTHONPATH=/opt/ismanager -v "$PWD/tests:/checks:ro" worker python /checks/live_asr.py
```
