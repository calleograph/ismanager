# UX-аудит IS Manager

27 ноября 2026 года. Исходная точка — v0.5.0, рабочее дерево `af55026`. Повторный проход выполнен на рабочем дереве при подготовке версии 0.6.0. Все учётные записи, документы, записи речи и названия на снимках учебные.

С обзора сотрудник теперь возвращается к пакету или достигнутому шагу анкеты за одно нажатие вместо двух. Администратор открывает события пользователя за один переход вместо трёх. При 10 000 результатах и 10 000 пакетах страница истории обезличивания уменьшилась с 1,49 МБ до 15,8 КБ. [Замеры времени и действий](#8-повторные-измерения) · [33 снимка экранов](#9-снимки-до-и-после)

## 1. Назначение и границы проверки

IS Manager объединяет четыре повседневные задачи специалиста ИБ. Он превращает русскую речь в редактируемый текст, обезличивает документы, генерирует пароли и собирает комплект документов из анкеты модели угроз. В установке на Python/Flask рабочие записи и права хранятся в SQLite, фоновая обработка выполняется в контейнерах. Администратор подключает каталог пользователей, обслуживает установку и задаёт правила обработки локальных или SMB-папок. Карта исходных проектов, маршрутов и обработчиков приведена в [PROJECT.md](../PROJECT.md).

В аудит вошли публичный обзор, загрузка и карточка записи, одиночная и пакетная обработка, четыре режима генератора, 11 шагов анкеты, списки материалов, вход, учётная запись, администрирование и страницы ошибок. Для первого прохода зафиксировали прежние пути и экраны, для второго повторили задачи на синтетических данных и проверили ошибки, большие списки и возврат к работе.

## 2. Пользователи и полномочия

| Кто работает | Что требуется |
| --- | --- |
| Сотрудник, впервые открывший ссылку | Выбрать один из четырёх инструментов без входа. Видеть результат или причину ошибки сразу после отправки. |
| Возвращающийся сотрудник | Найти свой материал по заданию, имени, номеру или дате. Продолжить с достигнутого шага, скачать собственный TXT или ZIP. У гостя эта возможность привязана к cookie посетителя. |
| Администратор | Пройти локальный или доменный вход с действующей политикой пароля и второго фактора, вернуться к целевой настройке, проверить систему, права и очередь. Личные материалы принадлежат конкретному рабочему пространству. |
| Сотрудник на телефоне, с клавиатурой или увеличением | Выполнить те же операции через видимые подписи, фокус и панели, помещающиеся в экран. Способ взаимодействия не предоставляет дополнительных прав. |

Проверка двух независимо созданных браузерных контекстов подтвердила, что чужие пакет и черновик отсутствуют в обзоре, а их прямые ссылки возвращают 404. Тесты приложения дополнительно проверяют владение, CSRF, доступ к загрузкам и административным операциям.

## 3. Карта реальных сценариев

| Частота | Путь и признак завершения |
| --- | --- |
| Ежедневно | Обзор → запись → загрузка → очередь и журнал с показаниями → редактор → сохранение правок → TXT с исправленным текстом. |
| Ежедневно | Обзор → текст или документ → предпросмотр → сохранить проверенный результат. Для пакета — выбор файлов → очередь → статусы каждого документа → ZIP с готовыми TXT. |
| Ежедневно | Обзор → пароли → готовый вариант → копирование. Для изменения состава доступны фраза, словарь, история и случайные символы, настройки длины и размещения вставки. |
| По мере подготовки документов | Профиль системы или импорт XLSX → 11 шагов → проверка → DOCX в ZIP. Повторный вход ведёт к предыдущему шагу или готовому архиву. |
| Повторная работа | Последние материалы → конкретный пакет или черновик. Более старые работы доступны из истории своего инструмента. |
| Первичная настройка | Вход администратора → обязательные действия учётной записи → настройки каталога → поиск и назначение пользователя или группы. Хранилища → ресурс → правило с выбранным источником и местом вывода. |
| По обращению | Пользователь → его события → CSV. Правило наблюдения → старый ошибочный файл → повтор. Состояние системы → характеристики или обслуживание. Для важных команд открывается отдельное подтверждение. |

## 4. Первоначальные измерения и метод

В Chromium проверяли одинаковые точки входа и конечный результат. Геометрию измеряли в CSS-пикселях от верха документа при 100%. Время пользовательского пути в таблице — измерение автоматизации от первого действия до видимого результата или загрузки. Оно включает задержки сети, обработчика, опроса и отрисовки. В малых сценариях возможна разница в десятые доли секунды между прогонами. Для серверных списков использовали отдельно указанную медиану пяти прогретых GET.

Клик — активация управляющего элемента, в сценариях текста учтён и клик для фокуса. Ввод в поле и подтверждение выбора в системном файловом окне не считаются дополнительными DOM-кликами. Переход — отображение другой страницы. В таблице «окна» учитывают диалог выбора файла, «подтв.» — отдельное обязательное подтверждение действия. Загруженный файл и введённый текст считаются одним полем каждый. Точка отсчёта для повторного скачивания — уже открытый список. Полные проходы анкеты и распознавания приведены отдельно от коротких путей получения готового результата.

До изменений главное меню частично выходило за видимую область в 36 из 144 сочетаний публичной страницы, окна и масштаба. При 1366×768 кнопка получения готовой стенограммы находилась на высоте 867 px, ZIP пакета — 752 px, поле исходного текста — 642 px. На телефоне соответствующие значения составляли 928, 811 и 631 px. Высота административного обзора на ноутбуке достигала 3502 px. При 10 000 подключённых ресурсах браузер получал 10 001 вариант в выборе папки.

## 6. Приоритеты

**P0.** Проверены границы доступа, сохранность обработанных материалов, контроль административных подтверждений и сведений в обратной ссылке. Приёмка требует успешного отрицательного сценария для чужого материала и успешного скачивания собственного результата.

**P1.** В первую очередь исправлены потеря контекста и повторного ввода, недоступная история старых ошибок, неограниченные выборки, положение основного действия и мобильная навигация. Эти дефекты влияли на завершение задачи или время ежедневной работы.

**P2.** Уточнены визуальная иерархия, читаемость чисел и подписей, состояния фокуса, пустые экраны и движение при наведении. Повторный проход добавил исправления компоновки при 150% и доступных имён сокращённой мобильной навигации.

## 7. Система дизайна и композиция

Рассмотрели обзор из равных плиток, обычный реестр документов и рабочий экран с отдельным входом в транскрибацию и общей зоной материалов. Выбрали третий вариант. Звуковая волна построена по амплитуде учебной русской записи из набора тестов. Она обозначает прикладную функцию и поставляется локальным WebP объёмом менее 1 КиБ. Второй рабочий акцент — собственный результат пользователя.

Общий контейнер до 1320 px выравнивает навигацию, формы и списки. На широком экране у обзора две области в отношении 1 к 1,14, на телефоне одна. Шаги отступов 4, 8, 12, 16, 24 и 32 px связывают плотные строки с группами действий. Заголовки набраны локальным Manrope, рабочий текст — Inter с кириллицей. Цвета текста, полей, фокуса, акцента и ошибок заданы отдельно для «Стекла», тёмной и светлой тем. Текущая страница и состояние имеют текстовое обозначение. Для выбора сетки и проверки фокуса использованы [Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview) и [критерии WCAG](https://www.w3.org/WAI/WCAG22/quickref/).

При наведении строка меняет фон, стрелка смещается на 2 px, волна — на 4 px. Большинство переходов занимает 160 мс. Эффекты учитывают тип указателя и предпочтение уменьшенного движения. Сравнили примеры реакций на нажатие и наведение в [Kinetics](https://kinetics.colorion.co/) и [подборке Proglib](https://proglib.io/p/top-38-hover-effektov-dlya-sovremennogo-veb-dizayna-v-2025-godu-2025-03-31).

Taste и design-taste-frontend применены к различимости четырёх инструментов. High-end-visual-design и frontend-design — к типографике, палитре и глубине поверхностей. Redesign-existing-projects — к переносу рабочих действий ближе к их результату. UI UX Pro Max использован при выборе плотности и сетки, Impeccable — при повторной проверке рабочих состояний, Agent Browser и Playwright — для сравнения реально отрисованных экранов.

Проверены последняя страница записей и анкет, длинные названия и поиск с учётом русских букв. Для старых ссылок на пакеты сохранён параметр `before_batch`.

При 30 000 вошедших пользователей поиск по синтетическому имени отдал одну строку, время полного перехода 2119→198 мс. Отдельно подняли OpenLDAP с 30 000 записями и служебным пользователем с доступом на чтение. При фокусе получили 12 пользователей и 5 групп. Поиск `ux29997` нашёл нужную запись за 0,312 с. Проверены отдельное назначение по UUID и выбор группы. Загрузка LDAP и число записей SQL — два независимых опыта.

## 10. Браузерная и техническая проверка

1. Agent Browser и Playwright открывали живые экземпляры. Контрольные размеры — 1280×800, 1366×768, 1440×900, 1512×982, 1920×1080, 390×844. Публичные экраны дополнительно прошли 320×640 и 768×1024. Реальный зум вкладки через Chromium `tabs.setZoom` проверяли на 100%, 125% и 150%, включая 213 эффективных CSS-пикселей. На шести публичных экранах выполнено 144 измерения каждой версии. Итог — ноль выходов документа за ширину экрана, обрезанных пунктов навигации, исключений JavaScript и непредусмотренных сетевых ошибок. В исходной версии замечена ошибка получения favicon.
2. Для десяти административных экранов прошли 180 сочетаний размера и зума. Страницы сохранили доступ к действиям и поместились по ширине. В отдельном проходе повторили поиск в LDAP, ошибку сетевого поиска ресурсов, сохранение выбранной папки, F5 с отменой ухода, обязательную смену пароля и возврат к исходной форме. Отмена отката остановила команду, подтверждение копирования доставило ровно один запрос тестовому системному помощнику. В 66 дополнительных проверках axe для 11 состояний, включая ошибку LDAP, учётную запись и выбор ресурса правила, автоматических нарушений не выявлено. На 30 из 66 сочетаний axe пометил отдельные узлы для ручной оценки контраста. Для 78 измеренных сочетаний текста и отрисованного фона на четырёх экранах отношение контраста составило от 5,90:1 до 14,85:1. Другие отмеченные административные узлы не оценивались вручную.
3. На шести публичных страницах запустили axe-core в трёх темах при размерах ноутбука и телефона — 36 проверок применимых правил WCAG A/AA без выявленных автоматикой нарушений. Порядок Tab, переход к основному содержимому, подписи, фокус при ошибке, уменьшенное движение и ввод с телефона проверяли отдельно. Повторное испытание с заполненными формами выявило расхождение между именем мобильной ссылки и видимым текстом. Исправление внесено в общий шаблон. На готовой стенограмме, профиле и заполненном банке угроз в трёх темах и двух размерах прошли ещё 18 полных запусков axe с нулём выявленных нарушений. Для 240 отмеченных образцов текста на отрисованных подложках наименьшее измеренное отношение контраста — 5,81:1. Ручной проход обнаружил перекрытие фокуса нижней панелью мастера. После настройки отступов прокрутки проверены по 58 элементов в обоих направлениях на 1366 px и по 52 на 390 и 320 px. Ещё 18 сканирований охватили сохранённое обезличивание, смешанный пакет с ошибкой и раскрытый состав сгенерированного пароля. Axe не выявил нарушений. В шести проверках «Стекла» для 191 отмеченного вхождения сопоставлены цвет текста и фактический фон под буквами. Минимальное измеренное отношение — 5,76:1.
4. Сквозные тесты провели через живые интерфейсы. Проверены HTTP, HTTPS, соединение через обратный прокси, медленная загрузка в GigaAM, TXT после правки, обработка двух доменных SMB-ресурсов, восстановление потерянного результата наблюдения и пакет с изолированной ошибкой PDF. Проверены серверная генерация паролей, ручное копирование в HTTP, запуск без JavaScript для импорта XLSX, шагов анкеты и получения DOCX. LDAP и Active Directory проверены на изолированных службах.
5. Образы web и worker собраны локально через Buildx с чистой сборкой, финальные изменения статических ресурсов включены в web-образ. На хосте прошли 175 тестов pytest и 10 вложенных проверок. Три проверки зависели от отсутствующих на хосте бинарных инструментов для DOC и OCR. В поставляемом окружении выполнена 71 проверка форматов, обработки и доступа, включая эти три, без пропусков. На хосте и в контейнере отмечены два предупреждения библиотеки LDAP об устаревших именах pyasn1. Проверены Python compileall, JavaScript и shell-синтаксис, Node-тест генератора, Ruff для критических ошибок Python и mypy девяти затронутых модулей с проверкой тел нетипизированных функций.

### Как повторить

Установите тестовые зависимости из [инструкции для разработчика](../PROJECT.md#запуск-проверок). В следующих командах `ORIGIN` — адрес отдельного экземпляра с пустым томом. Сценарий рабочего пространства создаёт на нём синтетический пакет и черновик. Для сканирования axe передайте локальный путь к `axe.min.js`. Для сетевых сценариев используются локальные теги собранных образов и подготовленный том весов GigaAM в режиме чтения.

```sh
python -m tests.live_workspace "$ORIGIN"
python -m tests.live_layout "$ORIGIN" --axe /path/to/axe.min.js
python -m tests.live_web
python -m tests.live_admin_ux
python -m tests.live_generators
python -m tests.live_network "$WEB_IMAGE" "$WORKER_IMAGE" --model-volume "$MODEL_VOLUME"
python -m tests.live_http_proxy "$WEB_IMAGE" "$WORKER_IMAGE" "$MODEL_VOLUME"
python -m tests.live_folder_watch "$WEB_IMAGE" "$WORKER_IMAGE" "$MODEL_VOLUME"
```

## 11. Ограничения и статус поставки

- Экспертные баллы и длительность автоматизированного действия характеризуют этот стенд. Пользовательского исследования с сотрудниками предприятия не проводилось. На скорость обработки реального пакета влияют формат, объём, OCR и железо.
- Сенсорный ввод проверен в эмуляции Chromium. Работа аппаратных экранных дикторов, системного файлового диалога и буфера обмена во всех версиях Windows, macOS, iOS и Android требует проверки на устройствах. Автоматическая проверка охватывает подмножество критериев WCAG.
- Для проверки обслуживания использован изолированный оператор. Обновление, откат или восстановление рабочей установки предприятия в этой задаче не выполнялись. Комплект DOCX и автоматически обезличенный или распознанный текст по-прежнему требуют содержательной проверки владельцем.
- Замеры относятся к сборке на момент аудита. Проверки обновления и дополнительной доработки компоновки при выпуске 0.6.0 описаны в [протоколе выпуска](VERIFICATION.md#060--27-ноября-2026).
