# Обезличивание и пароли в IS Manager

## Обезличивание

Вставьте текст или откройте файл в разделе «Обезличивание». «Предпросмотр без сохранения» позволяет сравнить исходник с результатом и увидеть число замен по категориям. «Обезличить и сохранить» добавляет результат в личную историю. Исходный текст виден при первом просмотре. История содержит обработанный текст, профиль, счётчики, предупреждения и время UTC. Результат по ссылке открывается в рабочем пространстве владельца. При работе без входа сохраните cookie этого браузера.

| Профиль | Обработка |
| --- | --- |
| Полный · Faceless | 240 правил каталогов Faceless для персональных данных, реквизитов, инфраструктуры и секретов, контекстные правила 1С и офтальмологических записей, строгий режим NER |
| Строгий · Переговорка | Распознавание людей, организаций и мест, согласованные обозначения с учётом русских падежей, поиск секретов и структурированных данных |
| Базовый · Переговорка | Краткая форма имени, организации по юридической форме и словарю, сохранение упоминаний мест |

При открытии формы выбран полный профиль Faceless со всеми группами. Для одиночной ручной обработки можно выбрать другой профиль или группы. Пароли, ключи, токены и строки подключения проверяются в каждом профиле. Для терминов конкретной организации есть отдельное поле, до 48 слов или фраз. Регистронезависимое сопоставление русских терминов учитывает падежи. Корпоративный словарь наполняет сам оператор при обработке. Весь анализ выполняется на сервере IS Manager.

Результат проходит независимую проверку секретов, контактов, реквизитов и сетевых адресов. При остаточном срабатывании движок делает дополнительный проход. Повторное срабатывание блокирует сохранение и экспорт. Перед передачей документа оператор проверяет спорные имена, OCR и возможность узнавания человека по контексту. Точность англоязычных имён зависит от написания и контекста. Метки полей и словарь оператора помогают распознать редкие имена.

### Пакет из браузера

В разделе **Обезличивание** выберите несколько документов в форме пакетной загрузки. Браузер передаёт их по одному, а сервер обрабатывает очередь в фоне. Оставьте вкладку открытой до окончания передачи. После приёма файлов страницу можно закрыть. К пакету можно вернуться в том же браузере. Пакеты, созданные под администратором, открываются после входа в эту учётную запись. В нём видны состояния отдельных файлов. На вкладке, с которой выполнялась загрузка, браузер показывает рядом с номером локальное имя документа до выхода из учётной записи. Готовые TXT можно скачать по одному или одним ZIP. Завершённый пакет можно удалить вместе с его результатами. Выходные имена нейтральны, чтобы фамилия или номер заявки из названия оригинала не попали в выгрузку.

Для пакетов и папок всегда применяется полный профиль Faceless с включёнными группами и независимой проверкой. Обработчик скрывает в том числе значения полей с паролями и короткими кодами. Для табличных выгрузок учитывается заголовок секретного столбца. При повреждении или шифровании документа, превышении лимита либо ошибке проверки файл получает отдельный статус. Остальная очередь продолжает работу.

При открытии пакета, обработанного до 0.5.0, страница помечает результаты по прежним правилам. Чтобы перепроверить исходные документы, создайте новый пакет. Приложение удалило временные оригиналы после завершения предыдущей обработки. Ранее скачанные ZIP и TXT остаются у получателей.

### Автоматически обрабатывать папку

1. Сохраните локальный или SMB-ресурс в **Система → Ресурсы хранения**. Доменную учётную запись задайте в самом ресурсе. [Подключение и проверка доступа](TRANSCRIPTION.md#подключить-ресурс)
2. В разделе **Обезличивание** откройте создание правила для папки либо перейдите в **Система → Наблюдение за папками → Добавить правило** и выберите **Обезличивание**.
3. Укажите входной ресурс и подпапку. По умолчанию результаты сохраняются в **Обезличено IS Manager** внутри входной папки. Можно выбрать другой подключённый ресурс. Включите наблюдение и сохраните правило.

Правило читает документы непосредственно в указанной папке. Вложенные каталоги подключаются отдельными правилами. Источник остаётся на месте. Обработчик ждёт, пока файл перестанет изменяться, и публикует проверенный UTF-8 TXT c нейтральным именем. Сопоставление входного и выходного файлов доступно администратору в журнале правила. Обработанная версия учитывается при следующих обходах. Папка вывода должна отличаться от входных папок обезличивания. При монтировании каталога сервера добавьте том и в сервис `redactor` по тому же пути под `/watch`, что и в `web`. Готовые SMB-подключения из интерфейса обходятся без изменения Compose. После обновления с 0.4.0 включённое правило проверит доступные оригиналы заново. Ранее скачанные результаты, копии, уже существующие архивные TXT и файлы, для которых удалён источник, требуют отдельной проверки у владельца.

### Файлы и экспорт

| Источник | Что попадает в обработку |
| --- | --- |
| TXT, MD, LOG, CSV, TSV, JSON, XML, YAML/YML, INI, CFG, CONF, ENV | Текст. При разборе CSV и TSV учитываются кодировка, разделитель, кавычки и многострочные ячейки |
| HTML, HTM | Видимый текст |
| DOC, RTF, DOCX, ODT | Текст документа. Для старого бинарного DOC используются Antiword и Catdoc. В DOCX учитываются также колонтитулы, примечания и сноски |
| Outlook MSG | Текстовое или HTML-тело, тема, отправитель и адресаты, до 64 вложений поддерживаемых форматов. Встроенные изображения обрабатывает OCR. Письмо с вложенным MSG, недоступным вложением или только с RTF-телом требует экспорта |
| XLS, XLSX, XLSM, XLSB, ODS | Значения ячеек. Поддерживаются в том числе таблицы Excel 2003 XML и HTML с расширением XLS, общие и встроенные строки XLSX. Макросы не исполняются |
| PDF | Текстовый слой и локальный OCR для сканов и смешанных страниц. При обработке учитываются ключи в ссылках и значения секретных полей, перенесённые на следующую строку |
| PNG, JPEG/JPG, TIFF/TIF | OCR средствами Tesseract для русского и английского языков |

В таблицах Word и Excel, CSV и HTML обработчик учитывает заголовки секретных столбцов. В реестре с колонками «Категория», «Исходное значение» и «Ожидаемое действие» он также учитывает тип данных и отметку об обнаружении или маскировании в каждой строке. Повтор значения в комментарии или другом месте того же документа также скрывается, в том числе при первом упоминании до записи в реестре.

Число файлов в выборе браузера не ограничивается приложением. Для пакета и папки предел одного документа составляет 64 МиБ, 2 000 000 знаков извлечённого текста и 300 страниц PDF. Разбор отдельного пакетного документа ограничен 15 минутами, а обработчик проверяет 30-минутный бюджет обезличивания между фрагментами. Для одиночной формы с интерактивным предпросмотром действуют пределы 12 МиБ, 60 000 знаков и 60 страниц PDF. При превышении вывод для этого файла блокируется целиком. Встроенные рисунки Office могут потребовать отдельной загрузки для OCR. Для плохо читаемого скана сверьте распознанные имена и цифры перед передачей текста.

Скачать можно TXT, DOCX, XLSX, ODT или ODS. Офисный файл создаётся заново из проверенного текста. Абзацы переносятся в документ, табуляции разделяют ячейки таблицы. Диаграммы, исходная вёрстка, стили, вложения, ссылки, макросы и исходные метаданные в результат не входят. Формулы в электронных таблицах экспортируются как обычный текст. Такой экспорт отличается от режима Faceless с редактированием исходного OOXML-пакета на месте. PDF и изображения экспортируются в виде текста.

### Реализация и зависимости

Каталоги Faceless из редакции `c464fde` перенесены в `app/privacy/faceless.json`. Алгоритм в `faceless.py` проверяет границы строк, локальные положительные и отрицательные контексты, группы значений, энтропию и контрольные суммы. Пересечения разрешаются по приоритету категории и длине совпадения. Код Python NER, морфологии, нормализации и независимой проверки основан на реализации LLM Provider `14f46f2`, развивающей встроенный движок «Переговорки».

Веса Navec и Slovnet извлекаются при сборке из Natasha 1.6.0. Проверяются закреплённые SHA-256 колеса и обоих файлов. Веб-процесс загружает модели с диска при первом обращении. Параметр `PRIVACY_NLP_DIR` указывает путь к локальным весам, в Docker это `/opt/nlp`. При их недоступности обработка прекращается. Для небольших матриц NER в образе установлены `OMP_NUM_THREADS=1` и `OPENBLAS_NUM_THREADS=1`.

Модели и лицензия из колеса Natasha размещаются отдельно от исходников IS Manager. MIT-лицензия колеса сохраняется рядом с весами. Библиотеки Slovnet, Navec, Razdel и pymorphy3 имеют лицензию MIT. Код пакета словарей pymorphy3-dicts-ru распространяется по MIT, исходные данные OpenCorpora — по CC BY-SA 3.0. В образ словарь устанавливается без изменения. [Natasha](https://github.com/natasha/natasha), [словари pymorphy3](https://github.com/no-plagiarism/pymorphy3-dicts), [OpenCorpora](https://opencorpora.org/dict.php), [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/)

NumPy поставляется под BSD-3-Clause, пакет regex — по условиям Apache-2.0 и CNRI-Python. Tesseract (Apache-2.0) и Poppler запускаются как отдельные системные программы в образе. Пакеты дистрибутива сохраняют свои лицензии в `/usr/share/doc`. [Tesseract](https://github.com/tesseract-ocr/tesseract), [Poppler](https://poppler.freedesktop.org/)

## Генератор паролей

Вкладка предлагает до семи различных вариантов. Каждый можно скопировать отдельно. Истории паролей в IS Manager нет.

| Режим | Параметры |
| --- | --- |
| Своя фраза | От трёх до пяти разных слов, транслитерация, случайная вставка. Минимальная итоговая длина — 15 символов |
| Слова из словаря | Два целых слова при пределе 12–15 символов, три при 16–18. Русские исходные слова видны в подсказке |
| Короткая история | Число, герой, действие и итог. Из каждой части берётся различимый префикс, под паролем показывается фраза |
| Случайные символы | Длина 4–64, обязательный символ из каждой выбранной группы, настраиваемый набор спецсимволов, исключение визуально похожих знаков |

Для словесных режимов можно выбрать положение вставки. Вставка содержит цифру от 2 до 9 и один или два спецсимвола. Короткая собственная фраза может быть предсказуемой.

По умолчанию варианты создаёт браузер средствами Web Crypto. В этом режиме фраза и пароль остаются в текущей вкладке. Выбор «На сервере IS Manager» включает Python-реализацию на `secrets`. Параметры передаются методом POST с проверкой сессии и CSRF. Ключевые значения не записываются в БД, журналы, cookie или браузерное хранилище. Ответ сервера запрещает кэширование. Используйте HTTPS.

Страница и серверная генерация находятся в `app/passwords.py`, локальная генерация и общие словари — в `app/static/passgen`. Варианты транслитерации, словари, положение вставки и четыре режима перенесены из Passgen.

## Проверка модулей разработчиком

Для проверки без Docker установите зависимости проекта, модели и языковые данные Tesseract. С жизненным циклом приложения работает стандартный набор unittest.

```sh
python -m pip install -r requirements.txt
export PRIVACY_NLP_DIR="$PWD/.venv/nlp"
python -m app.privacy.fetch_models "$PRIVACY_NLP_DIR"
OPENBLAS_NUM_THREADS=1 python -m unittest discover -s tests -p test_texttools.py -v
```
