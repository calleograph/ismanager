# Эксплуатация IS Manager

## Первая установка

Запускайте команды управления от владельца установки с доступом к Docker. Установщики работают с Ubuntu 24.04, Git, Python 3.10+ и Docker Compose v2 с поддержкой `up --wait`. Для установленного Docker используйте `./install.sh --shared-host` в свежем клоне. Скрипт определяет корень по собственному расположению. Для отдельного экземпляра используйте новый клон и новые `--name` и `--port`.

Первый запуск требует сетевого доступа к GitHub, реестру образов Python, Debian, PyPI, CDN PyTorch и GigaAM. При медленной сети обработчик продолжает подготовку модели после временной ошибки. Причину видно в `docker compose logs worker`. Установщик проверяет работоспособность веб-приложения и загрузку нейросети до создания администратора. При утрате вывода терминала выполните сброс.

```sh
docker compose exec -T web flask --app app admin-password
```

Сброс выдаёт новый первичный пароль, отзывает сеансы локального администратора и снимает его второй фактор. В обычном режиме двухфакторную защиту можно включить в **Учётная запись**. Приложение-аутентификатор принимает ключ вручную. Один и тот же код действует один раз.

## Каталог и доступ

Войдите локальным администратором и откройте **Система → Добавить подключение**. Укажите AD или OpenLDAP, LDAPS либо LDAP с STARTTLS, имя сервера, порт, Base DN и сервисную запись с доступом на чтение. Для внутреннего CA вставьте публичную цепочку PEM или загрузите сертификат из файла PEM/DER. Пароль сервисной записи хранится зашифрованным в БД. Пустое поле пароля при редактировании сохраняет действующий секрет.

Для нескольких каталогов укажите домен NetBIOS и суффикс UPN. Вход поддерживает короткое имя, форму `DOMAIN\user` и UPN. Подключения проверяются по заданному приоритету, при равном приоритете — по порядку добавления. Флаги входа пользователей и администраторов задаются отдельно. Настройте полные DN групп допуска и администраторов. Пустой список допуска разрешает вход активным учётным записям подключённого каталога. Права администратора назначаются членам отдельно указанных групп, включая вложенные. Локальный администратор сохраняет доступ при сбое каталога.

Сохраните подключение, снова откройте его и нажмите **Проверить**. Результат показывает DNS, TCP, TLS, bind сервисной записи и чтение базы. При указании тестового логина добавляются поиск и оценка групп, с паролем тестируется также вход пользователя. Изменение или удаление профиля отзывает связанные сеансы. Изменения групп в самом каталоге применяются при следующем входе. В разделе **Политика входа** задаются срок новых сеансов (по умолчанию 12 часов), лимиты попыток и обязательный второй фактор для администраторов. Немедленное завершение доступно в списке активных сеансов.

## Файлы, HTTPS и состояние

| Объект | Содержимое |
| --- | --- |
| `.env`, права 0600 | Секрет приложения и параметры экземпляра. Секрет нужен для расшифровки паролей каталога и TOTP |
| Том `DATA_VOLUME`, путь в контейнерах `/data` | SQLite, аудио, состояние очереди, TLS-сертификат и ключ |
| Том `models` у worker | Проверенные веса GigaAM. Их можно получить повторно |
| `.runtime/backups/` | Локальные резервные копии. Переносите копии на отдельный защищённый носитель |
| `.runtime/operator.log` | Вывод последней операции из браузера |
| `docker compose logs --tail=100 web worker` | Диагностика приложения и загрузки модели |

Для прямого HTTPS используется `/data/tls.pem`, содержащий приватный ключ и цепочку PEM. Чтобы установить выпущенный для сервера сертификат, подготовьте объединённый файл, затем выполните команды из каталога установки. Проверку сертификата выполните до перезапуска. Назначением TLS и сетевым доступом управляет администратор. Обратный прокси может использовать свой сертификат и передавать трафик приложению по HTTPS.

```sh
openssl x509 -in server-combined.pem -noout -subject -dates
docker compose exec -T web sh -ec 'umask 077; cat > /data/tls.next; python -c "import ssl; ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER).load_cert_chain(\"/data/tls.next\")" && mv /data/tls.next /data/tls.pem' < server-combined.pem
docker compose restart web
```

Храните результаты, TOTP-ключи, модели угроз и копии с учётом политики доступа вашей организации. Исходные файлы транскрибации удаляются вместе с записью по команде владельца. Общий том и резервные копии содержат рабочие данные; защищайте диск и доступ к Docker.

## Обновление и возврат версии

`scripts/manage.py check` получает теги из настроенного `origin`; `update` выбирает последнюю стабильную версию вида `vX.Y.Z` из истории основной ветки. Операции не выполняются параллельно. Перед переключением останавливаются web и worker, сохраняется согласованная копия. Каталог моделей переиспользуется. На время операции браузер получает HTTP 503, чтобы пользовательские записи не попали в частично обновлённое хранилище. При перезапуске помощник проверяет журнал незаконченного обновления. Ручное продолжение после сбоя — `./scripts/manage.py recover`. При неуспехе запуска восстанавливается прежняя версия, если новый код уже был запущен, используется снимок данных. Для перехода на предыдущий успешно установленный коммит выполните `scripts/manage.py rollback`. При ручном откате также создаётся копия текущего состояния. Отдельный возврат данных выполняется командой восстановления.

Браузерные операции принимает изолированный помощник systemd. Контейнер web имеет доступ только к его сокету с проверкой секрета. Для переустановки службы выполните `./install.sh --operator`. При установке без root используется пользовательская служба systemd. На сервере, где она должна работать после выхода из сеанса, администратор может включить linger для владельца установки. Для управления только из CLI установите с `--no-operator`.

## Резервные копии и восстановление

```sh
./scripts/manage.py backup
./scripts/manage.py restore /path/to/backup.tar
./scripts/manage.py status
```

Копия содержит базу, исходные записи, документы, TLS и секрет приложения. Архив хранится с правами владельца и не зашифрован. Для переноса на новый сервер установите ту же версию, затем восстановите архив. Восстановление проверяет целостность SQLite, извлекает архив в новый том и переключает приложение. Прежний том сохраняется. Модель речи будет использована из существующего тома или загружена заново. Операции копирования и восстановления кратковременно останавливают сервисы. Очистку старых томов и копий выполняйте по своей политике хранения.

Если начальная установка 0.1.0 остановилась с ошибкой импорта operator до создания томов, скачайте установщик актуального релиза повторно и запустите его из отдельного каталога с прежним `--dir`. Он сохранит ключ и перейдёт на исправленный релиз.

Если данные уже созданы в 0.1.0 или 0.1.1, для перехода на следующий выпуск скачайте свежий `install.sh` из GitHub и вызовите его с `--dir /opt/ismanager --ref v0.1.3` (подставьте последний стабильный тег). Он применит исправленный инструмент обновления из указанного стабильного релиза и сделает копию перед переключением.
