# Эксплуатация IS Manager

## Первая установка

Запускайте команды управления от владельца установки с доступом к Docker. На выделенной Ubuntu 24.04 установщик при необходимости ставит Git, Python, Docker Engine и Compose v2. На общем сервере подготовьте Git, Python 3.10+, Docker Engine и Compose v2 с поддержкой `up --wait`.

Первый запуск требует сетевого доступа к GitHub, реестру образов Python, Debian, PyPI, CDN PyTorch и GigaAM. При медленной сети обработчик продолжает подготовку модели после временной ошибки. Причину видно в `docker compose logs worker`. Установщик проверяет работоспособность веб-приложения и загрузку нейросети до создания администратора. При утрате вывода терминала выполните сброс.

```sh
docker compose exec -T web flask --app app admin-password
```

Сброс выдаёт новый первичный пароль, отзывает сеансы локального администратора и снимает его второй фактор. В обычном режиме двухфакторную защиту можно включить в **Учётная запись**. Приложение-аутентификатор принимает ключ вручную. Один и тот же код действует один раз.

### Размещение на общем сервере

Для первого экземпляра рядом с другими приложениями запустите скачанный установщик с `--shared-host --access http --port 18085`, подставив свой свободный порт. Он использует существующий Docker, создаёт свой Compose-проект, сеть, контейнеры и тома. Порт публикуется на IPv4-адресе локальной сети. Чтобы выбрать конкретный интерфейс, добавьте `--bind`. Если порт занят, выберите другой. Действующие сайты, прокси и правила межсетевого экрана остаются под управлением администратора.

Если на машине **уже работает IS Manager**, запуск установщика в его каталоге с новым `--port` меняет адрес этого экземпляра. Для второй независимой установки укажите отдельные каталог, имя Compose и порт. Команда использует установщик, скачанный по инструкции в README.

```sh
sudo bash "$HOME/install-ismanager.sh" --shared-host --dir /opt/ismanager-second --name ismanager-second --access http --port 18086
```

Каждый экземпляр получает собственную базу пользователей и документов, хранилище моделей, резервные копии и службу обновлений. Для одновременной работы с двумя экземплярами в одном браузере используйте разные имена хостов. Браузер привязывает cookie к хосту и пути независимо от порта.

## Вход и навигация

Нажмите **Вход администратора** в шапке или откройте нужную страницу в `/admin/`. После входа приложение возвращает к выбранному внутреннему экрану, при необходимости сначала предлагает сменить первичный пароль или подключить обязательный второй фактор. Для возврата используется разрешённый маршрут IS Manager и идентификатор объекта. Параметры произвольной ссылки и содержимое формы в сеанс не записываются.

В разделе **Система** доступны страницы **Состояние**, **Каталоги**, **Пользователи**, **Хранилища**, **Правила** и **Журнал**. На странице состояния находятся сетевой профиль, сведения об обработчике GigaAM, политика входа, обновления и резервные копии. В списках каталогов ищите по названию или серверу, в хранилищах — по названию, папке или серверу. В правилах можно сочетать поиск по названию или входной папке с фильтром назначения.

## Каталог и доступ

Войдите локальным администратором и откройте **Система → Каталоги → Добавить подключение**. Укажите AD или OpenLDAP, LDAPS либо LDAP с STARTTLS, имя сервера, порт, Base DN и сервисную запись с доступом на чтение. Для внутреннего CA вставьте публичную цепочку PEM или загрузите сертификат из файла PEM/DER. Пароль сервисной записи хранится зашифрованным в БД. Пустое поле пароля при редактировании сохраняет действующий секрет.

Главная страница и четыре рабочих раздела открыты по общему адресу. Подписанная cookie связывает загруженные записи, пакеты и черновики с текущим браузером. Ссылка на чужой результат его содержимое не открывает. Cookie сохраняется при перезапуске браузера и продлевается на семь дней при посещении. После её очистки или истечения срока создаётся новое рабочее пространство. Удалить ненужные документы можно в их разделах до очистки cookie. Для настроек, журналов, ресурсов SMB и обслуживания требуется вход администратора. При обновлении прежние материалы сохраняют владельцев. Если в версии 0.4.0 обычные доменные пользователи сохраняли документы, до обновления попросите их скачать нужные записи и комплекты. Во вновь открытом гостевом пространстве чужие материалы не появляются. Для восстановления пропущенной выгрузки администратор может поднять отдельный экземпляр прежней версии из копии перед обновлением.

Сохраните профиль каталога. В поле **Найти пользователя или группу** появятся первые записи из указанного Base DN. Введите часть имени или логина и выберите результат. Группа добавляется по DN и даёт права своим участникам с учётом вложенности. Индивидуальное назначение привязано к идентификатору пользователя в этом каталоге. Можно выбрать несколько записей. Чтобы отозвать право, снимите галочку у пользователя или удалите строку группы, затем сохраните подключение. Операции поиска выполняет сервисная учётная запись через LDAPS или STARTTLS. При пустом списке назначений работает локальный администратор.

Для нескольких каталогов укажите домен NetBIOS и суффикс UPN. Администраторы могут использовать короткое имя, форму `DOMAIN\user` или UPN. Профили проверяются по приоритету и порядку добавления. **Проверить** показывает DNS, TCP, TLS, bind сервисной записи и чтение базы. При указании тестового логина добавляются поиск, группы и право администрирования, с паролем проверяется вход. Изменение или удаление профиля отзывает его сеансы. Изменения групп в самом каталоге применяются при следующем входе. В разделе **Политика входа** задаются срок новых сеансов (по умолчанию 12 часов), лимиты попыток и обязательный второй фактор для администраторов. Откройте **Система → Пользователи**. Реестр показывает пользователей, которые уже входили, источник учётной записи, роль, состояние 2FA и число активных сеансов. Административный вход можно отключить для конкретной доменной учётной записи. Блокировка сразу завершает её сеансы и сохраняется при следующей проверке LDAP. Повторное включение возвращает право на новый вход. Локальный аварийный администратор сохраняет доступ.

В **Система → Журнал** доступны автор действия, затронутая учётная запись, тип события и время UTC. В списке пользователей доступны поиск по имени или логину и переключатель **Только с активными сеансами**. По ссылке **События** открывается журнал выбранной учётной записи. Кнопка **Скачать CSV** учитывает установленные фильтры. Панель **Обработчик GigaAM** показывает состояние связи и количество записей в очереди. Имена и содержимое пользовательских файлов остаются в рабочих разделах владельца.

## Автоматическая расшифровка папок

В разделе **Система → Хранилища** добавьте локальные пути и SMB с доменными учётными записями. На странице **Система → Правила** эти ресурсы выбираются для входа и вывода. Для каждого правила выберите назначение — транскрибация или обезличивание. При обезличивании исходники всегда сохраняются. ## Сетевой доступ

Раздел **Система → Состояние → Сетевой доступ** показывает настроенный внешний адрес и способ подключения. Сеть настраивается с хоста установки. Команды ниже применимы и к первой установке, и к действующему экземпляру. В рабочем экземпляре смена сети кратковременно перезапускает только веб-контейнер. Пользователи, документы и очередь транскрибации хранятся в прежних томах.

| Как заходят пользователи | Команда в каталоге установки |
| --- | --- |
| По HTTP из доверенной локальной сети | `sudo ./install.sh --access http` |
| По HTTP через конкретный интерфейс или порт | `sudo ./install.sh --access http --bind 192.168.1.25 --port 18084` |
| По HTTPS через прокси на том же сервере | `sudo ./install.sh --access proxy --host ismanager.example.org` |
| По HTTPS через прокси на отдельном сервере | `sudo ./install.sh --access proxy --host ismanager.example.org --bind 192.168.1.25 --port 18084 --trusted-proxy 192.168.1.10` |
| Напрямую по HTTPS через SSH-туннель | `sudo ./install.sh --access https --bind 127.0.0.1 --port 18443 --host localhost` |

В режиме HTTP установщик выбирает частный IPv4-адрес исходящего интерфейса и порт 18084. Адрес выводится в конце установки. На сервере с несколькими интерфейсами выберите нужный явно. По HTTP пароль, код 2FA, содержимое файлов и cookie передаются без шифрования. Переход с HTTP на HTTPS требует повторного входа.

### HTTP через существующий Nginx

Если пользователи открывают порт 8106, а веб-контейнер доступен Nginx на `127.0.0.1:18086`, укажите обе стороны подключения. В каталоге установки выполните:

```sh
sudo ./install.sh --shared-host --access proxy --bind 127.0.0.1 --port 18086 --public-url http://ismanager.example.org:8106
```

В действующем виртуальном хосте для этого имени и порта направьте `location /` на внутренний адрес. Для существующего порта используйте его текущую конфигурацию, чтобы запросы попадали в IS Manager. Пример сохраняет внешний Host и передаёт приложению исходный адрес клиента и схему HTTP. Проверьте конфигурацию через `nginx -t`, примените её и откройте внешний адрес. [Образец виртуального хоста](nginx-http.conf.example)

При переходе на TLS задайте `--access proxy --public-url https://ismanager.example.org` и переключите Nginx на HTTPS. Порт Docker можно оставить 18086. Для HTTP и HTTPS используются раздельные cookie.

### HTTPS через Nginx

1. Направьте имя, например `ismanager.example.org`, на обратный прокси и подготовьте действующий для этого имени сертификат с полной цепочкой. Если внешний порт отличается от 443, укажите его в `--host`, например `ismanager.example.org:9443`.
2. Включите режим `proxy` командой из таблицы. Если Nginx находится на хосте приложения, оставьте прослушивание backend на loopback. Установщик автоматически определит адрес шлюза Docker, с которого приходят запросы хостового прокси. Для прокси на другом сервере укажите точный адрес отправителя и разрешите доступ к порту backend только с этого сервера в сетевых правилах. Для нескольких доверенных прокси перечислите их IP через запятую.
3. Добавьте отдельный виртуальный хост в конфигурацию Nginx. Подставьте имя, пути сертификата и адрес backend. Образец задаёт лимит 513 МиБ для передачи аудио и видео размером до 512 МиБ с полями формы. [Конфигурация Nginx](nginx.conf.example)
4. Проверьте конфигурацию командой `sudo nginx -t`, затем примените её штатной командой прокси. Откройте `https://ismanager.example.org/healthz`, затем войдите в приложение через браузер. При работе через SSH-туннель с прямым HTTPS используйте `ssh -L 18443:127.0.0.1:18443 user@server` и откройте `https://localhost:18443/`.

Прокси передаёт исходный `Host` и перезаписывает `X-Forwarded-Proto` и `X-Forwarded-For` по данным соединения. Приложение сверяет публичное имя, использует адрес клиента для ограничения попыток входа и выставляет cookie с `Secure`. При отказе в доступе проверьте адрес TCP-пира, получаемый контейнером, внешний `Host` и значение `https` в заголовке схемы. Для отдельного Nginx-контейнера используйте доступный ему адрес upstream и точный статический IP самого прокси как доверенный.

При установке сначала проверяются Engine, Compose и Buildx, затем собираются образы GigaAM и веб-приложения и запускается проверка готовности трёх сервисов. Для наблюдения за первым скачиванием модели используйте `docker compose logs -f worker` в каталоге установки. На общем сервере проверьте наличие плагинов командами `docker compose version` и `docker buildx version`. Если Buildx отсутствует, установщик заранее сообщает о переходе на прежний сборщик Docker. Когда этот сборщик отключён в Docker, установите пакет `docker-buildx` из Ubuntu или `docker-buildx-plugin` из репозитория Docker.

## Файлы, HTTPS и состояние

| Объект | Содержимое |
| --- | --- |
| `.env`, права 0600 | Секрет приложения и параметры экземпляра. Секрет нужен для расшифровки паролей каталога и TOTP |
| Том `DATA_VOLUME`, путь в контейнерах `/data` | SQLite, аудио, состояние очереди, TLS-сертификат и ключ |
| Том `models` у worker | Проверенные веса GigaAM. Их можно получить повторно |
| `.runtime/backups/` | Локальные резервные копии. Переносите копии на отдельный защищённый носитель |
| `.runtime/operator.log` | Вывод последней операции из браузера |
| `docker compose logs --tail=100 web worker redactor` | Диагностика приложения и загрузки модели |

Для прямого HTTPS используется `/data/tls.pem`, содержащий приватный ключ и цепочку PEM. Чтобы установить выпущенный для сервера сертификат, подготовьте объединённый файл, затем выполните команды из каталога установки. Проверку сертификата выполните до перезапуска. Назначением TLS и сетевым доступом управляет администратор.

```sh
openssl x509 -in server-combined.pem -noout -subject -dates
docker compose exec -T web sh -ec 'umask 077; cat > /data/tls.next; python -c "import ssl; ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER).load_cert_chain(\"/data/tls.next\")" && mv /data/tls.next /data/tls.pem' < server-combined.pem
docker compose restart web
```

Храните результаты, TOTP-ключи, модели угроз и копии с учётом политики доступа вашей организации. Исходные файлы транскрибации удаляются вместе с записью по команде владельца. Общий том и резервные копии содержат рабочие данные; защищайте диск и доступ к Docker.

## Обновление и возврат версии

Откройте **Система → Состояние → Обновления и резервные копии** и нажмите **Проверить**. Панель показывает установленную версию и последний обнаруженный релиз. Для обновления нажмите **Обновить** и подтвердите операцию. При работе из 0.6.0 образы готовятся до остановки сервисов. После сборки помощник делает копию, переключает версию и дожидается готовности контейнеров. Пока приложение перезапускается, оставьте вкладку открытой. В ней появится результат операции. Перейдите в новый интерфейс по ссылке **Открыть новую версию**. При первом переходе со старой версии в браузере остаётся прежняя панель. [Описание обновления, отказа и отката в Wiki](../wiki/updates.md)

`scripts/manage.py check` получает теги из настроенного `origin`; `update` выбирает последнюю стабильную версию вида `vX.Y.Z` из истории основной ветки. Операции не выполняются параллельно. Перед переключением останавливаются web, worker и redactor, сохраняется согласованная копия. Каталог моделей переиспользуется. Во время сборки установленный экземпляр продолжает принимать запросы. При переключении приложение временно отвечает HTTP 503 или порт недоступен, пока перезапускается веб-контейнер. При перезапуске помощник проверяет журнал незаконченного обновления. Ручное продолжение после сбоя — `./scripts/manage.py recover`. При неуспехе запуска восстанавливается прежняя версия, если новый код уже был запущен, используется снимок данных. Для перехода на предыдущий успешно установленный коммит выполните `scripts/manage.py rollback`. Для отката на 0.1.x сначала включите прямой HTTPS. Эти версии умели принимать только TLS. При ручном откате также создаётся копия текущего состояния. Отдельный возврат данных выполняется командой восстановления.

Браузерные операции принимает изолированный помощник systemd. Контейнер web имеет доступ только к его сокету с проверкой секрета. Для переустановки службы выполните `./install.sh --operator`. При установке без root используется пользовательская служба systemd. На сервере, где она должна работать после выхода из сеанса, администратор может включить linger для владельца установки. Для управления из CLI установите с `--no-operator`. Выбор сохраняется при повторной установке. Панель показывает команды `python3 scripts/manage.py check`, `update` и `backup` для каталога установки. Повторно включите веб-управление командой `./install.sh --operator` от имени владельца установки.

В разделе «Технические характеристики» каждые три секунды обновляются загрузка CPU и занятая память сервера. Отдельные строки показывают, сколько ядер и памяти использует контейнер GigaAM. Значение 1,5 занятого ядра соответствует полутора полностью загруженным логическим ядрам за интервал измерения. При остановленном обработчике его показатели исчезают после устаревания снимка.

## Резервные копии и восстановление

```sh
./scripts/manage.py backup
./scripts/manage.py restore /path/to/backup.tar
./scripts/manage.py status
```

Копия содержит базу, исходные записи, документы, TLS и секрет приложения. Временные оригиналы из пакетной очереди обезличивания исключены из копии. После восстановления готовые результаты доступны, а для незавершённых ручных задач может потребоваться повторная загрузка. Входные документы и опубликованные TXT на локальных или SMB-ресурсах копируются средствами соответствующего хранилища. Архив хранится с правами владельца и не зашифрован. Для переноса на новый сервер установите ту же версию, затем восстановите архив. Восстановление проверяет целостность SQLite, извлекает архив в новый том и переключает приложение. Прежний том сохраняется. Модель речи будет использована из существующего тома или загружена заново. Операции копирования и восстановления кратковременно останавливают сервисы. Очистку старых томов и копий выполняйте по своей политике хранения.

Если начальная установка 0.1.0 остановилась с ошибкой импорта operator до создания томов, скачайте установщик актуального релиза повторно и запустите его из отдельного каталога с прежним `--dir`. Он сохранит ключ и перейдёт на исправленный релиз.

Если данные уже созданы в 0.1.0 или 0.1.1, для перехода на следующий выпуск скачайте свежий `install.sh` из GitHub и вызовите его с `--dir /opt/ismanager --ref v0.6.1` (подставьте нужный последний стабильный тег). Он применит исправленный инструмент обновления из указанного стабильного релиза и сделает копию перед переключением.
