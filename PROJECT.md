# IS Manager — архитектура и сопровождение

IS Manager объединяет четыре локальных инструмента с общей учётной записью. Проект начат в пустом каталоге в ноябре 2026 года. [Требования к продукту](docs/MASTER_PROMPT.md)

## Карта переноса

| Источник | Что использует IS Manager |
| --- | --- |
| Переговорка | Порядок первичного входа, отдельные профили LDAP, TLS и вложенные группы, стеклянная оболочка, схема выпуска через теги Git, ранняя проверка состояния, GigaAM v3 E2E RNNT и речевая сегментация |
| MFA Gate | Синхронная логика bind и групп AD/OpenLDAP, диагностика соединения, тестовый каталог, самодостаточные шрифты и иконки темы. Код адаптирован из Apache-2.0 версии |
| Faceless | Общие каталоги детектирования для документов, персональных данных и секретов, контекстные проверки, обработка файлов |
| LLM Provider и Переговорка | Локальные Slovnet/Navec, морфология, разрешение упоминаний, стабильные замены и независимая проверка результата |
| Passgen | Словари, четыре режима, транслитерация и Web Crypto. Серверная реализация использует Python secrets |
| Генератор модели угроз | 11 шагов, профиль ИС, таблицы расчёта, 243 угрозы, рекомендации и состав выходного комплекта. Публичные шаблоны документов подготовлены без клиентских образцов |

## Устройство приложения

**web** обслуживает HTTPS, серверные шаблоны Flask/Jinja, формы, настройки и скачивание результатов. У каждого инструмента свой Blueprint. Общий слой проверяет серверный сеанс, обязательную смену первичного пароля, роль и CSRF до обработки формы. Модули ограничивают запросы владельцем. Веб-приложение также вызывает ограниченные по размеру и времени локальные инструменты извлечения текста и OCR. Статические файлы, шрифты, иконки и браузерный генератор раздаются из образа.

**worker** читает очередь транскрибации из SQLite и обрабатывает один материал за раз. В его образе FFmpeg, Silero VAD, PyTorch и GigaAM. Веса лежат в отдельном томе; доступность зависит от фактической загрузки модели. Очередь переживает перезапуск. На одном томе допускается один активный обработчик, защищённый файловой блокировкой.

**Хранилище** использует SQLite WAL на локальном томе между контейнерами. Записи очереди, учётные записи, профили каталогов, результаты обезличивания и архивы документов согласованно копируются вместе с исходными файлами записей. Этот вариант предназначен для одного узла. Горизонтальный запуск на нескольких серверах потребует сетевой БД и другого механизма координации worker.

**Эксплуатация** вынесена на хост. Установщик подготавливает изолированные ресурсы Docker. CLI и помощник systemd используют один механизм обновления и резервного копирования под файловой блокировкой. Образы помечаются Git-ревизией. Веб-приложение и worker работают без root и Docker API.

| Путь | Ответственность |
| --- | --- |
| `app/__init__.py`, `app/db.py` | Фабрика приложения, маршрутизация, CSRF, сессии и общая схема данных |
| `app/auth.py`, `app/admin.py`, `app/directory.py` | Первичный вход, TOTP, каталоги, доступ и диагностика |
| `app/transcription.py`, `app/worker.py`, `app/asr_store.py` | Работа с аудио и видео, очередь и распознавание |
| `app/redaction.py`, `app/privacy/` | Детектирование, обработка файлов и экспорт |
| `app/passwords.py`, `app/static/passgen/` | Два способа генерации с едиными словарями |
| `app/threats.py`, `app/threat_model/` | Анкета, расчёты и документы |
| `scripts/manage.py`, `scripts/host_helper.py` | Релизы, проверка, копирование и восстановление |

## Запуск проверок

```sh
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt pytest playwright
export PRIVACY_NLP_DIR="$PWD/.venv/nlp" OPENBLAS_NUM_THREADS=1
python -m app.privacy.fetch_models "$PRIVACY_NLP_DIR"
python -m pytest -q tests
tests/ldap/run.sh
python -m playwright install chromium
python -m tests.live_web
```

Для OCR нужны Tesseract с языками rus/eng и Poppler. Для live-теста LDAP нужен Docker. Практическая проверка worker использует отдельный процесс и синтетическую русскую фразу. [Транскрибация](docs/TRANSCRIPTION.md)

## Границы версии

Русская речь поддерживается локальной моделью GigaAM; редактор позволяет сохранить исходный вывод и вручную исправить стенограмму. Проверку качества обезличивания на материалах своей организации выполняет владелец. Модель угроз использует версионированный справочник в поставке. Документы требуют проверки и утверждения специалистом. Существующие настройки соседних приложений и клиентские документы в новую установку не импортируются.
